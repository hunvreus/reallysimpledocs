# Components

RSD ships a small set of MDX components for documentation pages that need richer examples than plain Markdown. They are thin Astro components built on Basecoat primitives where possible.

Use `.md` for normal pages. Use `.mdx` when a page needs these components.

<Code
  title="Import components"
  lang="mdx"
  code={`import { Callout, Preview, Tabs } from "reallysimpledocs/components";`}
/>

## Callout

Use `Callout` for important notes, warnings, and destructive or irreversible actions. It maps to Basecoat alert styles and supports a small set of documentation-specific variants.

### Usage

<Code
  lang="mdx"
  code={`<Callout type="tip" title="Good to know">
  Keep normal docs pages as Markdown.
</Callout>`}
/>

### Examples

<Callout type="note" title="Note">
  Use a callout when the surrounding paragraph is not enough.
</Callout>

<Callout type="tip" title="Tip">
  Use MDX only for pages that need components or custom layout.
</Callout>

<Callout type="warning" title="Warning">
  Avoid putting app-only imports in reusable documentation examples.
</Callout>

<Callout type="danger" title="Destructive">
  This variant is for irreversible actions, security risks, or migration warnings.
</Callout>

<Callout type="note" icon={false} title="No icon">
  Set `icon={false}` when the message should read like normal copy.
</Callout>

### Options

| Prop | Type | Default | Notes |
| --- | --- | --- | --- |
| `type` | `"note" \| "tip" \| "warning" \| "danger"` | `"note"` | Main variant. |
| `variant` | `"note" \| "tip" \| "warning" \| "danger"` | `undefined` | Alias for `type`; wins when both are set. |
| `title` | `string` | Variant label | Heading displayed in the alert. |
| `icon` | `false` | `undefined` | Set to `false` to hide the icon. |
| `class` | `string` | `""` | Extra classes applied to the alert root. |

## Preview

Use `Preview` for component examples where readers need to see the rendered result and the source code together.

### Usage

<Code
  lang="mdx"
  code={`<Preview code={source} lang="html" class="max-w-sm">
  <button type="button" class="btn">Save changes</button>
</Preview>`}
/>

### Examples

<Preview code={buttonSource} lang="html" class="max-w-sm">
  <button type="button" class="btn">Save changes</button>
</Preview>

<Preview code={astroConfig} lang="js" title="astro.config.mjs" defaultTab="code">
  <Callout type="tip" title="Configuration">
    This example opens on the source tab.
  </Callout>
</Preview>

### Options

| Prop | Type | Default | Notes |
| --- | --- | --- | --- |
| `code` | `string` | `""` | Source shown in the code tab. |
| `lang` | `string` | `"html"` | Language passed to Shiki. |
| `title` | `string` | `undefined` | Optional title above the code block. |
| `defaultTab` | `"preview" \| "code"` | `"preview"` | Initial active tab. |
| `class` | `string` | `""` | Extra classes applied to the preview canvas. |

## Code

Use `Code` when a normal fenced code block is not enough, usually because the example needs a title or needs to be passed into another component.

### Usage

<Code
  lang="mdx"
  code={`<Code title="Install" lang="bash" code={installCommand} />`}
/>

### Examples

<Code title="Install" lang="bash" code={installCommand} />

<Code title="astro.config.mjs" lang="js" code={astroConfig} />

### Options

| Prop | Type | Default | Notes |
| --- | --- | --- | --- |
| `code` | `string` | `""` | Code to highlight. |
| `lang` | `string` | `"text"` | Language passed to Shiki. |
| `title` | `string` | `undefined` | Optional header label. |
| `class` | `string` | `""` | Extra classes applied to the code wrapper. |

## Tabs

Use `Tabs` for mutually exclusive examples, such as package managers, frameworks, or operating systems.

The API is data-driven because Astro components cannot reliably inspect child component props at runtime.

### Usage

<Code
  lang="mdx"
  code={`<Tabs
  tabs={[
    { label: "npm", slot: "npm" },
    { label: "pnpm", slot: "pnpm" },
  ]}
>
  <Code slot="npm" lang="bash" code="npm install reallysimpledocs@beta" />
  <Code slot="pnpm" lang="bash" code="pnpm add reallysimpledocs@beta" />
</Tabs>`}
/>

### Examples

<Tabs
  tabs={[
    { label: "npm", slot: "npm" },
    { label: "pnpm", slot: "pnpm" },
    { label: "bun", slot: "bun" },
  ]}
>
  <Code slot="npm" lang="bash" code={`npm install reallysimpledocs@beta basecoat-css@beta tailwindcss`} />
  <Code slot="pnpm" lang="bash" code={`pnpm add reallysimpledocs@beta basecoat-css@beta tailwindcss`} />
  <Code slot="bun" lang="bash" code={`bun add reallysimpledocs@beta basecoat-css@beta tailwindcss`} />
</Tabs>

<Tabs
  variant="line"
  defaultTab="manual"
  tabs={[
    { label: "Integration", slot: "integration" },
    { label: "Manual", slot: "manual" },
  ]}
>
  <Callout slot="integration" type="tip" title="Recommended">
    Let the integration wire routes and assets for the docs section.
  </Callout>
  <Callout slot="manual" type="warning" title="Manual setup">
    Manual wiring is useful for debugging, but it is not the normal install path.
  </Callout>
</Tabs>

### Options

| Prop | Type | Default | Notes |
| --- | --- | --- | --- |
| `tabs` | `{ label, slot, value?, disabled? }[]` | `[]` | Tab metadata. `slot` must match a slotted child. |
| `defaultTab` | `string` | First enabled tab | Initial active tab value. |
| `orientation` | `"horizontal" \| "vertical"` | `"horizontal"` | Passed to the tablist. |
| `variant` | `string` | `undefined` | Basecoat tab variant, such as `"line"`. |
| `class` | `string` | `""` | Extra classes applied to the tabs root. |

## Steps

Use `Steps` for ordered setup flows. It renders a numbered rail similar to common install guides instead of relying on browser list styling.

### Usage

<Code
  lang="mdx"
  code={`<Steps>
  <Step title="Install packages">
    Add RSD, Basecoat, and Tailwind CSS.
  </Step>
  <Step title="Configure Astro">
    Add the RSD integration to astro.config.mjs.
  </Step>
</Steps>`}
/>

### Examples

<Steps>
  <Step title="Install packages">
    Add RSD, Basecoat, and Tailwind CSS to your Astro app.
    <Code lang="bash" code={`pnpm add reallysimpledocs@beta basecoat-css@beta tailwindcss`} />
  </Step>
  <Step title="Create docs">
    Add `docs/docs.json` and one or more Markdown or MDX pages.
  </Step>
  <Step title="Run Astro">
    Start the dev server and open the URL printed by Astro.
  </Step>
</Steps>

### Options

| Component | Prop | Type | Default | Notes |
| --- | --- | --- | --- | --- |
| `Steps` | `class` | `string` | `""` | Extra classes applied to the ordered list. |
| `Step` | `title` | `string` | `undefined` | Optional heading. |
| `Step` | `class` | `string` | `""` | Extra classes applied to the list item. |

## Card and CardGrid

Use `Card` and `CardGrid` for small groups of related links, concepts, or next actions.

### Usage

<Code
  lang="mdx"
  code={`<CardGrid>
  <Card title="Markdown" description="The default content format.">
    Best for normal docs pages.
  </Card>
  <Card title="MDX" href="/components/">
    Best for component examples.
  </Card>
</CardGrid>`}
/>

### Examples

<CardGrid>
  <Card title="Markdown" description="The default content format.">
    Best for normal docs pages.
  </Card>
  <Card title="MDX" description="The advanced content format." href="/components/">
    Best for components and previews.
  </Card>
</CardGrid>

<Card title="Custom width" description="Use class overrides for layout changes." class="max-w-sm">
  This card keeps Basecoat styling and only changes its outer sizing.
</Card>

### Options

| Component | Prop | Type | Default | Notes |
| --- | --- | --- | --- | --- |
| `Card` | `title` | `string` | `undefined` | Main card heading. |
| `Card` | `description` | `string` | `undefined` | Muted text below the title. |
| `Card` | `href` | `string` | `undefined` | Renders the card as a link. |
| `Card` | `class` | `string` | `""` | Extra classes applied to the card root. |
| `CardGrid` | `class` | `string` | `""` | Extra classes applied to the grid root. |

## Badge

Use `Badge` for short status labels. Do not use it for large blocks of explanatory text.

### Usage

<Code lang="mdx" code={`<Badge variant="secondary">Beta</Badge>`} />

### Examples

<div class="flex flex-wrap gap-2">
  <Badge variant="primary">Primary</Badge>
  <Badge variant="secondary">Secondary</Badge>
  <Badge variant="outline">Outline</Badge>
  <Badge variant="ghost">Ghost</Badge>
  <Badge variant="destructive">Destructive</Badge>
</div>

### Options

| Prop | Type | Default | Notes |
| --- | --- | --- | --- |
| `variant` | `"primary" \| "secondary" \| "destructive" \| "outline" \| "ghost" \| "link"` | `"secondary"` | Basecoat badge class. |
| `class` | `string` | `""` | Extra classes applied to the badge root. |

## LinkButton

Use `LinkButton` for navigation actions that should look like buttons but behave like links.

### Usage

<Code lang="mdx" code={`<LinkButton href="/install/" variant="secondary">Install</LinkButton>`} />

### Examples

<div class="flex flex-wrap gap-2">
  <LinkButton href="/install/">Install</LinkButton>
  <LinkButton href="/customize/" variant="secondary">Customize</LinkButton>
  <LinkButton href="https://github.com/hunvreus/reallysimpledocs" variant="outline" target="_blank" rel="noreferrer">
    GitHub
  </LinkButton>
</div>

### Options

| Prop | Type | Default | Notes |
| --- | --- | --- | --- |
| `href` | `string` | Required | Link target. |
| `variant` | `"default" \| "secondary" \| "outline" \| "ghost" \| "link"` | `"default"` | Basecoat button class. |
| `target` | `string` | `undefined` | Link target attribute. |
| `rel` | `string` | `undefined` | Link rel attribute. |
| `class` | `string` | `""` | Extra classes applied to the link root. |
